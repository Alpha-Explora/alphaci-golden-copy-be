## Decisions fixed for implementation

- `ALPHACI_EDITION` selects the deployment manifest and defaults to `enterprise`
  for this Enterprise trunk. Hosted tenant selection remains behind the same
  request-scoped port and can replace the manifest source without changing
  guards or controllers.
- `CAPABILITY_MANIFEST_SOURCE` is the runtime seam for static manifests now and
  a signed/licensed source later; no license verification is added here.
- `/api/v1/capabilities` adds `edition` and `capabilityKeys`; its existing
  compatibility fields remain present and are projected from the resolved set
  where they represent a capability.
- `CapabilityGuard` uses `@RequiresCapability()` metadata, throws 404 for an
  absent composition key, and is ordered before `SubscriptionGuard`.
- Build profiles are `hosted` (`saas`, `edu`) and `enterprise` (`enterprise`).
  The backend profile ceiling is enforced by a profile exclusion map and a
  compiled-output conformance gate; the frontend uses the surface registry to
  stub excluded feature barrels.
- The backend publishes `@alphaci/capability-catalog` as a small package
  artifact. Until a registry is configured, the frontend test/build fixture
  consumes the package from a local packed artifact; sibling-checkout sync is
  retained only as a migration helper, not as the contract.

## PR 3: Capability guard and endpoint migration

**Backend files:**

- Create a kernel-owned capability decorator and `CapabilityGuard`.
- Read required keys through Nest `Reflector`; no metadata means allow.
- Resolve the request subject from the authenticated session/workspace context
  without making the guard own persistence.
- Migrate genuine capability checks from `EnvFeatureGuard` to metadata, with
  guard order `SessionAuthGuard, CapabilityGuard, SubscriptionGuard`.
- Delete `EnvFeatureGuard` and its tests after parity tests pass.
- Add 404/402/order/metadata tests and an architecture assertion that no
  controller imports the deleted guard.

**Acceptance:** out-of-pack requests return 404 before Billing can return 402,
inside-pack unentitled requests retain Billing's existing 402 response, and provider
`config.enabled`, DTO `request.enabled`, session security, and mock billing
flags are not migrated.
